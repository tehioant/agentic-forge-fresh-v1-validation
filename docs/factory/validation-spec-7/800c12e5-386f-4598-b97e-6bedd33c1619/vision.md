# Agentic Forge — whole-product vision

Antoine supplies or explicitly approves a product idea. Forge works with him in the originating conversation: challenge assumptions, recommend choices, and leave product and technical decisions to Antoine. The resolved interview becomes usable specifications, not a transcript disguised as a build plan.

The intended long-term loop is **grill-me → to-spec → to-tickets → implement/test → simplify → independent Standards/Spec review → controlled merge → integrated verification**. Only the finite current milestone becomes executable work. Completing it invites another interview for the same product; absent user input never authorizes a self-invented iteration.

## Operating model

GitHub is the shared handoff: versioned specifications and decision records, issues/dependencies for work, and PRs for delivery. A small durable control record correlates project, iteration, stage and evidence; it does not replace GitHub specifications.

Q30 accepted Python for a deterministic controller outside Hermes core, initially on the existing server. Q8 keeps each product's programming language and user-facing language as separate operator decisions. This documentation-only validation has no product UI and makes no locale choice.

Future engineering uses fresh role workers with enforced whole-process isolation. Independent review, tests, CI and controlled integration remain mandatory. Ordinary merges freeze while main is broken; gated recovery is permitted (Q16 clarified by Q19). Stuck engineering yields an independent diagnostic report for Antoine to choose the direction. No new spending or chargeable fallback is authorized, and workers do not inherit personal credentials or beta context.

## Finite validation milestone

**Only ticket #7's planning slice is current:** use the actual selected grill-me/grilling instructions against the genuine originating conversation, run to-spec on its resolved decisions, publish the milestone, vision and original provenance to the approved private validation repository, and read back the exact immutable docs and ready-for-agent specification issue. The handoff contains GitHub references and leaves execution disabled.

Ticket #8 owns to-tickets. Ticket reservation, engineering workers, scheduling, model admission, deployment/recovery execution and the next iteration are future capabilities here—not implicit executable backlog.
