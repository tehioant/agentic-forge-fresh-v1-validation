## Solution

Use the actual selected **grill-me → grilling → to-spec** instructions in the originating conversation. Ask the currently unblocked decision frontier with recommendations, wait for real answers, and preserve Antoine's authority over product, stack, programming-language and user-facing-language choices. Automatically publish its matching ready-for-agent issue, a separate whole-product vision and original decision provenance in the onboarded GitHub repository, then read back the exact immutable revision and issue. No additional routine approval or operator command advances synthesis/publication. Stop after this GitHub handoff: #8 owns to-tickets.

## Implementation Decisions

- Reuse the trusted Python CLI and durable iteration record. A thin same-conversation assignment composes the exact selected instructions; a read-only completion operation verifies the GitHub handoff. No second interview engine, generic skill framework or new publisher.
- The conversational agent executes grilling and prose synthesis. A heading validator, source catalog or successful process exit does not prove that method. Retain actual loading/tool execution correlated to the assignment, genuine interview, adaptation and published revision.
- Preserve real questions, recommendations, literal answers, actor/message references and interpretations separately. Expand accepted recommendations into concrete decisions without changing the original answer. Q19 clarifies Q16's freeze: ordinary merges stop while gated recovery may proceed.
- Q30 accepted Python for the controller; Q17/Q27 selected GitHub. Q8 keeps per-product programming and user-facing language decisions with the user. This documentation-only validation has no UI or separately chosen locale.
- Q6/Q11 adapt away only routine shared-understanding/spec/test-seam/batch confirmations. Unresolved substantive choices, spending approval and unchanged security/review gates still pause affected work.
- Resolve explicit selected planning sources and their real dependency closure; pin exact content. Missing, ambiguous, altered or unavailable inputs invalidate affected evidence. Do not select unrelated future-stage skills.
- Publish adjacent milestone, vision and provenance documents at an immutable Git commit in the verified repository. The ready-for-agent issue body exactly matches the milestone snapshot. Preserve the parent specification issue.
- Completion records only GitHub issue/document references, repository and commit identity, and leaves execution disabled. Later ticket synthesis reads GitHub, not hidden local interview state.
